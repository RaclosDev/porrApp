RESUMEN DE CAMBIOS REALIZADOS
==============================

1. Auto-selección de liga
   - Archivo: frontend/src/context/AppContext.jsx
   - Qué: Añadido useEffect que al cargar la app (cuando userName cambia) obtiene
     las ligas del usuario vía fetchMyGroups(). Si solo tiene 1 liga, la selecciona
     automáticamente. Si tiene 0 o 2+, fuerza Porra Global (id 1).
   - Por qué: Antes solo se auto-seleccionaba en la página /mis-ligas; al entrar
     directamente a otras secciones se quedaba con lo que hubiera en localStorage
     (o el default a id 1, pero no funcionaba bien). Se movió la lógica al
     AppContext para que ocurra globalmente.

2. Falta campo r32 en BetDataDTO
   - Archivos:
       src/main/java/com/porra/mundial/dto/BetDataDTO.java
       src/main/java/com/porra/mundial/service/HashTransitionService.java
   - Qué: El DTO no tenía el campo r32, solo r16, qf, sf. La BetViewer (frontend)
     lo esperaba para renderizar la ronda de 32 (Dieciseisavos). Se añadió el
     campo, su persistencia en saveRelationalPredictions() y su reconstrucción en
     rebuildBetDataDtoFromTables().
   - Por qué: Sin r32, el bracket se mostraba vacío. Faltó al migrar del viejo
     formato hash a las tablas relacionales.

3. Nombres de campo incorrectos en Layout.jsx (Ver Mi Porra)
   - Archivo: frontend/src/components/Layout.jsx
   - Qué: El botón "Ver Mi Porra" buscaba h.name (inexistente) en vez de
     h.participantName, y accedía a ?.id en vez de ?.key.
   - Por qué: La API devuelve participantName y key, no name ni id. El botón
     nunca encontraba la apuesta del usuario.

4. Null safety en rebuildBetDataDtoFromTables
   - Archivo: src/main/java/com/porra/mundial/service/HashTransitionService.java
   - Qué: Añadidos null checks en gp.getTeam(), finalMatch.getHomeTeam(),
     extra.getChampionTeam(), etc.
   - Por qué: Si algún registro tenía un equipo nulo (por migraciones antiguas
     o datos inconsistentes), se lanzaba NullPointerException y el endpoint
     GET /api/bets/{id} devolvía error 500.

5. Captura de errores en BetController y BetViewer
   - Archivos:
       src/main/java/com/porra/mundial/controller/BetController.java
       frontend/src/components/BetViewer.jsx
   - Qué: BetController ahora captura Exception genérica y devuelve un JSON
     con el mensaje de error. BetViewer muestra un modal con el error en vez
     de desaparecer sin decir nada.
   - Por qué: Antes BetViewer hacía return null si había error, silenciando
     completamente el fallo sin feedback para el usuario.

6. Seguridad: GET /api/bets/{id} daba 403 Forbidden
   - Archivo: src/main/java/com/porra/mundial/config/SecurityConfig.java
   - Qué: Cambiado .requestMatchers(HttpMethod.GET, "/api/bets") a
     .requestMatchers(HttpMethod.GET, "/api/bets/**") para que cubra también
     /api/bets/{id}.
   - Por qué: BetViewer usa fetch() sin token JWT. La regla antigua solo
     permitía acceso público al listado exacto /api/bets, no a las rutas
     con ID. Caía en el catch-all /api/** que requiere autenticación.
